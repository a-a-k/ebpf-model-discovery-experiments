# Petclinic iteration-4 contract

The adapter runs Spring Petclinic Microservices at pinned revision
[`3858f9c630cf989bb6809a86edf47c2be78dc9f1`](https://github.com/spring-petclinic/spring-petclinic-microservices/tree/3858f9c630cf989bb6809a86edf47c2be78dc9f1).
It reuses the qualified two-guest v3 deployment and native collection, but v4
adds no experiment response deadline. HAProxy request clocks are disabled, and
the study-injected Spring Cloud Gateway `Retry` and route `CircuitBreaker`
filters are absent. Readiness and process-control timeouts remain technical
guards, not application outcome criteria.

## Pinned behavior behind the contracts

- [`OwnerResource.findAll` and `findOwner`](https://github.com/spring-petclinic/spring-petclinic-microservices/blob/3858f9c630cf989bb6809a86edf47c2be78dc9f1/spring-petclinic-customers-service/src/main/java/org/springframework/samples/petclinic/customers/web/OwnerResource.java)
  call their repository directly; list owners and owner details therefore have
  a customers-to-MySQL obligation.
- [`ApiGatewayController.getOwnerDetails`](https://github.com/spring-petclinic/spring-petclinic-microservices/blob/3858f9c630cf989bb6809a86edf47c2be78dc9f1/spring-petclinic-api-gateway/src/main/java/org/springframework/samples/petclinic/api/boundary/web/ApiGatewayController.java)
  requires the customers result and attempts the visits result. Its upstream
  application circuit breaker can replace a visits error with empty visits.
  This native upstream fallback is intentionally preserved; the exact body
  oracle rejects that HTTP-200 response when pinned visits are missing.
- [`VisitResource.create`](https://github.com/spring-petclinic/spring-petclinic-microservices/blob/3858f9c630cf989bb6809a86edf47c2be78dc9f1/spring-petclinic-visits-service/src/main/java/org/springframework/samples/petclinic/visits/web/VisitResource.java)
  saves the visit through `VisitRepository`. HTTP 201 is only an
  acknowledgement: the external oracle independently requires one exact row
  with the acknowledged ID, pet, date and opaque description marker.
- [`VetResource.showResourcesVetList`](https://github.com/spring-petclinic/spring-petclinic-microservices/blob/3858f9c630cf989bb6809a86edf47c2be78dc9f1/spring-petclinic-vets-service/src/main/java/org/springframework/samples/petclinic/vets/web/VetResource.java)
  is `@Cacheable("vets")`. Gateway-to-vets is mandatory, while the vets-to-MySQL
  call is conditional on a cache miss and remains unknown when that condition
  is not observed.

## Shared database attribution

Customers, visits and vets are configured against the deployment's shared
MySQL endpoint. The inventory helper reads resolved Compose files and returns
the datasource endpoints and selected-fault aliases. These facts may annotate
already recovered Bering nodes and database dependencies only. They never add a
node or edge. Matching aliases do not independently prove that two observations
refer to one physical database instance; native database spans and eBPF aliases
remain source-qualified evidence. The owner-details contract deliberately keeps
the customers-to-MySQL and visits-to-MySQL obligations separate even when both
resolve to the selected shared deployment endpoint.

The four external response contracts use the immutable seed fixture derived
from the pinned SQL. A completed mismatch is false, incomplete transport or an
unavailable SQL census is unknown, and duration is descriptive only.
