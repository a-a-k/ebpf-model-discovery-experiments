# Observed-context baseline

The context baseline combines two observed edge views under the same operation
contracts, aliases, placements, replica inventory and metadata available to the
other methods.

The original canonical namespaced Bering graph keeps every existing edge record
and its endpoint set. A second pass of the same pinned Bering receives the same
unmodified mixed OTLP request bodies through the ordinary OTLP endpoint. Request
bytes, order, hashes and emitter roles are retained, and both views use the same
supplied alias table and admission rules.

The union adds previously absent observed SERVER-child edges only when their
canonical endpoint services already exist in the original graph. The joint view
must satisfy Bering's unambiguous parent/child guard. It adds no CLIENT fallback
edges, endpoints, services or inferred physical identities. Semantic conflicts
remain explicit uncertainty. The union is recorded as a derived graph together
with both original snapshots and its exact derivation.

Operation binding, metadata attachment and Sheaft calculation use the same
implementation as the other methods. Forecasts and their manifests are frozen
before target traffic. A reused forecast references its original model and must
equal that forecast completely, including unavailable and DB results. Reuse does
not create another model execution or independent observation.

Evaluation records context-baseline separately against the same aggregate,
per-state and DB-up/down external outcomes. Additional Bering passes, simulations,
preparation, failures and transfers remain in the cost inventory. The baseline
is a simple combination of observed information; no algorithmic or predictive
advantage is assumed.
