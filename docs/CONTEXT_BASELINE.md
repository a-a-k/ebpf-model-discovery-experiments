# Paired context baseline: decision before implementation

The original criterion is feasibility of eBPF graph discovery and useful Sheaft
simulation with absent or incomplete native tracing, judged against independent
application outcomes. Cost superiority is not an original requirement. The full
three-collector, three-system, three-mode, three-repeat matrix and all ten
operations remain required. No positive result or accuracy gate is assumed.

Both the main agent and independent skeptic give ORIGINAL-feasibility design GO
to one paired cheap-combination baseline, after actual review of catalog audits
41145186233, 41145190491 and 41146378650. These inspect immutable original6ef
captures; they are diagnostics, not new primary forecasts. Partial OBI has117
catalog SERVER spans whose unique parents are in the frozen SDK prefix rather
than the eBPF prefix. All literal fields and IDs survive raw-to-input conversion.
All172 catalog children have no SDK child-ID collision, and their relevant
parent/child variants have no conflicting attributes. The eBPF/native domain
split is an encoder policy, not proof of independent trace universes.

The strongest simple baseline retains the entire original canonical namespaced
graph, including every existing edge field and its strict endpoint set. A second
actual pinned Bering pass receives the same unmodified mixed OTLP request bodies
through the ordinary OTLP endpoint. Its original emitter roles, request order,
bytes and hashes remain recorded. Apply the same supplied alias table/admission
to both actual views. Import only previously absent actual SERVER-child edge IDs
whose canonical endpoint services already exist in the original graph. Bering's
unchanged unambiguous-parent/child guard must hold in the joint view. Do not import
CLIENT fallback edges, extra endpoints, new services or inferred physical identity.
Existing edges retain their complete original records; different descriptive
statistics remain visible in the joint artifact. True semantic identity conflicts
remain explicit uncertainty, not an arbitrary choice.

This is a direct union of observed edge views, not a novel algorithm or an
improvement claim. Joint-only ingestion is not an equivalent replacement:
SourceKind affects eBPF peer enrichment and SERVER/gRPC endpoint interpretation.
The original SDK-only, eBPF-only and namespaced combined arms remain unchanged.
The new paired baseline uses the same Store, entry evidence, supplied semantics,
inventory, operation binding, metadata attachment and actual Sheaft path. Extract
that existing per-operation path once rather than creating another implementation.
The union is a derived graph, never described as an emitted Bering snapshot.
Preserve both actual models/snapshots/quality and an exact union derivation.

All collectors and all scenarios receive this same baseline. Compute its model
and predictions inside the existing forecast phase before Study.freeze and any
target traffic. Keep its forecasts in a separate explicit file and compare them
with the same independent external outcomes. Never turn a post-target saved
diagnostic into a primary prediction. Single-source equivalence and an unchanged
union permit explicitly recorded reuse; do not invent extra execution or treat
copied predictions as independent measurements.

Charge all second-pass Bering work, Sheaft runs, preparation, CI, failed attempts,
retention and early stopping. Human preparation time remains unknown. No advantage
over the direct contract/inventory predicate or equivalent arithmetic is claimed.
No product API, generic validation framework, retry layer, raw rewrite or
experimental deadline is introduced. Actual code, saved paired output and final
common-source qualification need independent review before main81. Main81 remains
held; existing f60 qualification is retained as evidence for its unchanged paths.

Evaluation reuses the existing per-forecast error/outcome calculation for the
explicit `context-baseline` method. It reads the separate forecast file, requires
its forecasts/manifest/variant provenance to belong to the pre-target freeze,
and checks each available forecast's actual Sheaft model. A reused forecast must
equal the original combined forecast exactly and reference its original model;
no copied model or execution is invented. Original three-method rows and external
attempt counts remain unchanged. Historical evaluations without this policy keep
their original behavior. Repeated method rows are not independent external trials.

The saved-facts reader keeps the original three-method coverage check and checks
the paired method separately. Its fixed-file review binds every union input to
the pre-target freeze, checks the actual joint serve configuration and complete
accepted request sequence, reconstructs the supplied alias projection and entire
union independently, and inspects the seven-link operation metadata derivation.
Reuse requires complete forecast equality, including unavailable rows. Paired
evaluations must retain the frozen unknown/DB reasons and the same aggregate and
per-state external outcomes as combined. This reader does not rescore outcomes.
Accepted sidecars bind body hashes, byte counts, order and storage form. HTTP
Content-Type and Content-Encoding come from the same frozen manifest and reviewed
replay implementation; actual transmitted header bytes were not separately
captured. The paired source profile stays inactive until the final common commit
has passed independent review.
