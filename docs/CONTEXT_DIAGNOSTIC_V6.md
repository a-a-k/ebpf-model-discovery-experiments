# Separate context witness diagnostic

This implements the independently approved diagnostic design of 6 November
2026. It does not authorize execution, open MAIN, add primary cells, fit a model,
or replace the full 108-cell study. The workflow has no push trigger. No parent
record or execution approval is supplied by this implementation.

For each SDK mode, full and partial separately, the fixed treatments are none,
OBI with propagation `all`, and the same OBI with propagation `disabled`.
The latter literal is accepted by the parser in the exact pinned
[OBI source](https://github.com/open-telemetry/opentelemetry-ebpf-instrumentation/blob/b28e4e7fe0a01f1961b7c4747a13b8ff486d6fec/pkg/config/ebpf_tracer.go).
Primary OBI configuration remains unchanged. The diagnostic-local subclass
changes only that field and its descriptive metadata.

Each mode has 27 intended logical operations: three arms, three operations, and
three external context conditions, once per combination. Each arm therefore has
nine operations and 18 HTTP step intentions. All three arms contain 54 individually
identified HTTP step intentions. Both modes total 54 operations and 108 step
intentions. The ordinary adapter preserves failed responses and unattempted
dependent suffixes; they are not retried to obtain a positive witness. Natural
inputs carry no external W3C context. The other inputs use distinct valid W3C
parents with sampled flags 01 and 00. Identifiers are opaque, not topology.

The parent must be a separately reviewed, published **shared blueprint**
artifact, not a capture archive. The tracked parent record contains:

- `schema: separate-context-diagnostic-v6`, `system: otel_demo`, matching `mode`;
- explicit `diagnostic_execution_GO`, `root_diagnostic_execution_GO`, and
  `independent_diagnostic_execution_GO`, all true only after the separate
  source/observer execution review;
- `parent_run_id`, `parent_source`, `artifact_id`, `artifact_bytes`,
  `artifact_digest` for the actual immutable GitHub publication;
- `repetition` (9, 10, or 11), `parent_stage`, and `parent_smoke`, preserving the
  original v6 blueprint identity; these repetitions are not extra diagnostic
  repetitions;
- `shared_tar_bytes`, `shared_materialized_bytes`, `shared_tar_sha256`,
  `block_plan_sha256`, `golden_sha256`, and `blueprint_sha256`.

The dispatch binds the exact record SHA. API origin, name, expiry, size and
digest are checked before download. The shared tar and inner guest/application
seals are checked again inside Actions. The derivative keeps the parent image
IDs and SDK settings. All shared bytes, modes and inventory claims are verified.
Its only application configuration additions are the
readonly observer mount, its output directory, and the wrapped existing
frontend instrumentation options. Resolved configuration is generated by the
real frozen guest Compose parser before any diagnostic deployment. Every arm
uses that same derivative and fresh guest disks. Image equality does not imply
runtime-file or performance equivalence to the primary environment.
The actual frontend image, readonly source mounts, observer SHA and container
environment are recorded in each arm. Actual OBI config bytes, `/config.yaml`
mount and `OTEL_EBPF_BPF_CONTEXT_PROPAGATION` override are checked; an absent
override preserves the pinned YAML value. No primary OBI source is modified.

The existing HTTP options and any previous hook remain. The observer records
literal selected Node header values, the passed SDK span and the active span
separately. The pinned [HTTP instrumentation](https://github.com/open-telemetry/opentelemetry-js/blob/experimental/v0.221.0/experimental/packages/opentelemetry-instrumentation-http/src/http.ts)
invokes its incoming hook within the active request context, but that does not
justify assuming the two span objects are identical. The HTTP2 wrapper records
the original dispatch arguments and actual session/stream identifiers. It does
not change headers, samplers, providers, propagators, or SDK context and creates
no spans. A valid nonrecording context remains distinct from no context and
from absence of an exported span. Actual unsampled behavior still requires
observer qualification; unit fixtures are not that evidence.
The observer records the actual installed HTTP package version and its own
runtime source SHA. Missing version/source/sequence evidence is UNKNOWN.

Guest packet capture begins before collectors or applications create relevant
connections. The identical filter `tcp and not port 22` excludes only
infrastructure SSH/SCP traffic, including application image transfers; planned
HTTP/RPC edges do not use that port. Actions extracts TCP payloads with tshark and decodes HTTP2 header
blocks with pinned hpack 4.1.0. Both TCP prefixes and the peer's initial SETTINGS
are required: the peer constrains client header encoding. SYN/preface absence, conflicting or missing TCP
bytes, incomplete frame/header blocks, unsupported table settings, TLS, packet
drops or missing drop counters produce UNKNOWN. No TLS decryption, missing
context imputation, header-writer attribution, or SDK parentage inference is
performed. Incoming Node API values and outgoing HTTP2 arguments are not
mislabelled as wire bytes. A missing/ambiguous SDK hook is UNKNOWN.

Raw diagnostic wire/native/agent exports, observer logs, failed attempts,
changed runtime source, parent/derivative manifests, configuration and cost
receipts are retained separately. Parent image archives and guest templates
remain at their original publication rather than being duplicated. Preparation,
fresh clones, image restoration, controls, wire capture/decode, transfers,
failures, CI and retention all count. Job wall time is not CPU time or billing.
Human and unmetered work remain unknown. There is no arbitrary model-worker
CPU/RAM cap, paid runner or retry framework. The standard public worker and the
maximum six-hour job boundary are retained. All original primary qualification
work continues independently.
