## Retained records and original inputs

The original runtime-dependency producer already used incremental `json.dump`.
It nevertheless built a large list, repeated the records inside a roughly 1 GB
manifest, and required whole-manifest readers to materialize that array. The new
producer preserves the original validated loop and its order, consumes it at the
same checkpoint stage, and atomically writes every record to a separate UTF-8
JSONL file. The manifest lists and binds that file by size, SHA-256 and record
count. Legacy arrays and the existing list-returning API remain supported.
Conflicting or unbound references are rejected. Raw observation, accounting,
snapshot, SQLite, source, binary and before/after identity guards remain.
