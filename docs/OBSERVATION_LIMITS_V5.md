# Iteration 5 observation limits

This note records two mechanisms established from retained iteration-5 evidence. It does not repair or recompute a result, change an admission decision, or claim that one observation source is generally superior.

## Petclinic native endpoint identity

In [OBI Petclinic/full main run `40924968145`](https://github.com/a-a-k/ebpf-model-discovery-experiments/actions/runs/40924968145) seed 6, the frozen native raw input contains both `http.route` and `url.path`. Representative retained spans contain route values `customers`, `vets`, and `visits`, while their URL paths are `/api/customer/owners`, `/api/vet/vets`, and `/api/visit/owners/1/pets/1/visits`. The stable source is [campaign artifact `12927257991`](https://github.com/a-a-k/ebpf-model-discovery-experiments/actions/runs/40924968145/artifacts/12927257991), member `toolchain/inputs/native/raw/exports/native-000400.json`, SHA-256 `ab99cbd2d00b1290f73fc28bfd3a731b18ca132717dcb0c19be540c2af562724`. The exact reviewed examples are committed in [`results/iteration-5/diagnostics/pc-full-native-route/native-route-examples.json`](../results/iteration-5/diagnostics/pc-full-native-route/native-route-examples.json).

Pinned Bering 1.3.0 commit `70d4145d3e26f11d8b3fb5be8917c50c1c6d8c2a` selects endpoint path attributes in the order `http.route`, `url.path`, `http.target` in [`inferEndpointDetails`](https://github.com/MB3R-Lab/Bering/blob/70d4145d3e26f11d8b3fb5be8917c50c1c6d8c2a/internal/discovery/discovery.go#L422-L465). It normalizes the selected route. The retained native graph therefore has gateway endpoint IDs `GET /customers`, `GET /vets`, and `POST /visits`. The external operation contracts ask for the concrete URL paths above, so the saved bindings have no exact entry candidate and retain `entry_endpoint_missing_or_ambiguous`.

This is a representation-and-binding mechanism, not evidence that the native traces lacked the URL information or that native tracing is generally inferior. Selecting or combining another attribute was not evaluated here and is not asserted to satisfy the remaining call, database, or simulation obligations. The original input, graph, binding, forecast, outcome, and independent GO remain unchanged.

## DeepFlow ambient-load circuit breaker

DeepFlow OTel/absent [smoke run `40942447288`](https://github.com/a-a-k/ebpf-model-discovery-experiments/actions/runs/40942447288) failed the selected-agent control on guest A before application workload. Its retained node-A agent log records the official load-guard trigger followed by `Running` to `Disabled` with `melted_down=true` after the `Load15` relative-load check crossed the configured default. Guest B supplied the comparison capture. The failure remains a zero-operation technical attempt with its elapsed and preparation costs retained; it is not application- or protocol-negative evidence.

The stable sources are [compact artifact `12929535044`](https://github.com/a-a-k/ebpf-model-discovery-experiments/actions/runs/40942447288/artifacts/12929535044) (API SHA-256 `00c3d7d9faada13408bb917ea05d7ad7392a0d42ee3ec30387a136ef25112746`) and [full campaign artifact `12927583844`](https://github.com/a-a-k/ebpf-model-discovery-experiments/actions/runs/40942447288/artifacts/12927583844) (API SHA-256 `6b8908edb75c0c6efd6192e1bcf8c381c979b8abc958ed687739919317975404`). Compact members `observations/final-a-collector.log` and `final-b-collector.log` have SHA-256 `a963094837778f5846e71a1df270f7a53db5b040114c6e65b1d24e684dcb6cd8` and `cab04ebceb255abf0114703b411c00bf53963f4683ba6f4dd84db8fef6bcc8de`; full-artifact members `observations/deepflow-agent-standalone-{a,b}.yaml` both have SHA-256 `e81df46e4512b4efdb9a593beeddd4f7ca0ad44648d6de92da6f9a56978a6ca3`.

At pinned DeepFlow v7.2.3 commit `9a1219fa5cf1471ba2ec8742019661567d98002e`, [`RelativeSysLoad`](https://github.com/deepflowio/deepflow/blob/9a1219fa5cf1471ba2ec8742019661567d98002e/agent/src/config/config.rs#L2597-L2622) defaults to `trigger_threshold: 1.0`, `recovery_threshold: 0.9`, and `metric: Load15`. [`SystemLoadGuard::check`](https://github.com/deepflowio/deepflow/blob/9a1219fa5cf1471ba2ec8742019661567d98002e/agent/src/utils/guard.rs#L84-L142) divides load by the reported CPU count (`system.cpus().len()`) and treats zero trigger or recovery as disabling this guard; it does not establish an affinity-available CPU count. The check raises or clears the guard exception; the surrounding guard loop performs the agent state transition.

Research commit `6a616c685c10a7e17a80b1dda452d9da9e02a693` serializes explicit zero trigger and recovery values for that ambient-load guard in all DeepFlow arms. It does not alter other guards, collector source, codec, identity rules, workload, or resource envelope. The fixed OTel/absent smoke `40948057864` is still pending, so this note does not claim that the revision succeeded or that the earlier miss had no additional cause. Its emitted runtime YAML and acquisition evidence must be reviewed before that setting is admitted.
