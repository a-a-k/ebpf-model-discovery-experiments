# Prospective Social Network outcome correction

The correction tests the original question: whether observation-derived operation
models support external outcome forecasts when SDK tracing is absent or
incomplete. It does not assume an advantage over the equally informed direct
conditional calculation or cheap observed-context union.

All 36 Social Network input cells are selected in advance: three SDK modes,
three repetitions and NONE/OBI/Coroot/DeepFlow. All three operations remain.
Petclinic and OTel data are unaffected. Original observations, model publications,
forecasts and validation outcomes remain immutable historical evidence.

## Outcomes and treatment laws

The application and its Lua code stay at the original pinned configuration.
Compose success means HTTP success with the acknowledgement marker. Timeline
success means HTTP success and the stable fixture in the parsed timeline. Neither
event proves a successful compose MongoDB write or durability.

| Operation | Controlled-replica point | Selected MongoDB down, replicas up |
| --- | --- | --- |
| Compose acknowledgement | A OR B: 0.875 in the fixed 4/2/1/1 state mixture | 1 under the declared-error mask and fixed prefix conditions |
| Read home timeline | 1 under the fixed unrelated-service conditions | 1; the selected UserTimeline MongoDB is off this read's path |
| Read user timeline | A OR B: 0.875 in the same mixture | 1 with the registered preserved warm Redis fixture and fulfilled PostStorage |

These are prospective conditional forecasts, not guaranteed measurements. All
misses and unknown outcomes remain results. They are never grounds for retrying
a technically complete target or selecting a different input.

The pinned ComposePost C++ processor sends a declared ServiceException in a
normal T_REPLY; its Lua client decodes but ignores `se`. A user-timeline Mongo
write error therefore prevents the later Redis/Home calls without preventing
the ACK. Ordinary child transport/C++ exceptions can become TApplicationException
and HTTP failure. The primary replica model explicitly assumes fail-stop
transport behavior and noncongested pools, with unvaried services fulfilled.
The historical happy-path list remains a conservative graph-admission
requirement; it is not presented as an unconditional AND definition of ACK.

ReadUserTimeline is different: its Lua receiver checks declared exceptions, but
the C++ handler does not check a failed Mongo cursor and retains Redis IDs for
PostStorage. Successful readiness/reset establishes the untouched stable fixture
in Redis. Source inspection does not require exactly one stored post: preparation
retries may create duplicates. The selected Mongo can be attempted during the
fallback, so it is not called off-path. The same source/fixture/error knowledge
is supplied to graph methods and the direct baseline. Missing graph structure
or selected-endpoint attribution remains UNKNOWN for graph-based forecasts;
it does not artificially suppress the direct baseline.

## Execution

The [registered input plan](compose-ack-correction-plan.json) selects exact
original shared/model artifacts and canonical forecast-manifest hashes. Workers
verify original ZIPs, package inventories and frozen files. They reuse the
original logical observed graphs, quality and entry proofs; no Bering discovery
or new observation acquisition is needed. Supplied metadata adds no graph edges.
Corrected predicates run through the unchanged pinned Sheaft executable and are
checked against the deterministic graph law.

Nine block jobs freeze all four arms. A single barrier seals all nine blocks
before any of the 36 fresh validation deployments. Each target uses its original
sealed blueprint on new guest overlays, the original workload and SDK/collector
controls, and an independent worker. The original frozen family classification
may be applied to new observations; it is not refitted. Preparation rows, the
20 DB attempts split 7/7/6, unknown outcomes and all retries remain retained.

The workflow uses full standard workers and 360-minute limits. The target matrix
allows all 36 workers; GitHub applies the account's actual available concurrency.
Large source bodies stay in Actions. New freezes, raw target archives and result
receipts are verified into a Release. An oversized raw archive is losslessly
split. Publication recovery uploads only safe outer TAR containers, with all
original Linux filenames retained inside them.

The first correction run completed all 36 measurements and saved their 864
derived rows, but lost the raw captures: the target archive used a model-only
packing option, and the fallback rejected an upstream filename containing `*`.
Those aggregates and all failed-worker costs remain historical evidence; they
are not independently replayable raw captures. The fixed recovery repeats all 36
target cases against the exact nine forecasts and original barrier registered
in [the frozen input manifest](compose-ack-frozen-inputs.json). It does not
rediscover, recompile or refit models. All cases were selected for replacement
because of missing raw publications, before inspecting forecast accuracy.
Current recovery source/run identities are recorded separately from the original
forecast source/run. An actual publication fixture checks safe container delivery
with `*` inside the TAR and a forced publication failure before measurements.

Costs include the original reused preparation/models and new source/CI/review,
imports, predicate compilation, simulation, fresh guests, collectors, traffic,
oracles, classification, transfers, storage, failures and retries. Human work
remains unknown. Phase telemetry is nested within whole-worker intervals and is
not added again. No complete cost-superiority claim is made.
