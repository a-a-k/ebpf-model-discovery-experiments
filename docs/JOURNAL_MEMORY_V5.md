# Journal preparation memory repair

The original criterion remains eBPF observations → Procrustes → Bering graph →
Sheaft prediction, checked against independent application outcomes with the same
semantic information and complete costs as the direct baseline. This repair does
not establish a scientific, predictive, or effort advantage.

Source inspection found that `_journal_transports` simultaneously retained every
encoded and decoded transport event, including both response text and base64.
It ran even if no observation could use nonce-based enclosure evidence. Several
retained DeathStarBench jobs ended with shutdown 143 after calibration and very
little available memory/swap. Their precise shutdown cause is not established.

The strongest simple implementation baseline is a streamed journal index with
late loading of the unchanged evidence rows. The proposed causal change is lower
memory retention during preparation; no measurement/result filter is introduced.
The root agent and independent skeptic both gave ORIGINAL-criterion design GO
before implementation (2026-10-29). Actual-code review and saved-data Actions
validation are required before affected new campaign starts.

The implementation keeps existing nonce, method, route, terminal-exchange and
ambiguity rules. It reads the journal only when an existing observation can use
an enclosure. Under the journal lock it captures a maximum sequence and streams
that prefix into thin references. Full original rows are restored one exchange
at a time, verified against their exact event hashes, and serialized unchanged
in the evidence. Later appended rows cannot alter the captured prefix. The full
journal remains retained. No request/status/body filter, cap, clock tolerance,
workload change or forecast refit is involved.

Synthetic checks compare exact pre-repair transport evidence bytes, duplicate
and unknown handling, append behavior and tamper rejection; a large-body fixture
checks Python allocation without setting an experimental memory threshold.
Saved-data validation retains old/current source identities, source integrity,
semantic/evidence equality and execution costs. Small-input allocation results
must not be generalized to a full campaign. Failed runs and repair/validation
costs remain part of the history; preparation versions confound collector-only
cost comparisons.

The exact implementation at `5cfdd7c` passed CI `40941821118` and saved-journal
validation [40941966903](https://github.com/a-a-k/ebpf-model-discovery-experiments/actions/runs/40941966903).
Independent actual-output review verified the complete 18,080-byte output ZIP
against API SHA-256 `037006a988a37828d055e21d2cb53a21444898ad42af0a4b775017f77b3b8e0d`.
Actions verified the whole pinned source artifact and compared all 144 request
transports in the 706-row journal: complete canonical transport bytes, per-request
hashes and ambiguity handling matched. The full canonical stream was 1,347,695
bytes with SHA-256 `5d3d323003489db1e1036f75daaa38c421001181a1249998a30d90d7303ccafb`.
Both worker processes returned zero. This establishes saved-evidence equivalence;
the small packet does not prove a full-campaign memory bound or shutdown cause.

Previously qualified matching-setting execution resumed at that exact revision.
Earlier failures and older running attempts retain their original source and
cost attribution; no saved graph, forecast or outcome was recomputed by this check.
