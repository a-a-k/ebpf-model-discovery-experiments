# Uploaded checkpoint copies and parent disk headroom

The original study criterion remains all 81 comparable cases through actual
collector observations, Bering, Sheaft and independent outcomes under absent or
partial SDK tracing. Operations, supplied semantics, information, limits,
counts, models, trials, faults and outcome selection are unchanged.

The first T full6 social-network parent, run 41261041075/job 124714202937,
failed at 05:26:55 UTC on 2026-11-01. Its actual GitHub runner annotation says
`No space left on device`. The worker had succeeded; this does not identify
which parent file or exact subphase exhausted storage. Only the uploaded
checkpoint remains, so the case is incomplete and receives no successful score.

The simple repair releases the parent's redundant uploaded checkpoint payload
after its last read. The existing code has already validated every payload
hash, the binaries, and its logical index before this boundary. Before removing
anything, the repair checks the exact owned sibling `training-checkpoint` path,
the available original Actions artifact's ID/name/run/source/digest/size, the
complete local census and every local payload hash again. It unlinks only those
listed copies. The original `manifest.json`, `ready.json` and `release.json`
remain byte-identical; the manifest can itself be large. Live campaign data,
index, journals, binaries, VM disks and model inputs are separate originals.

The audit records logical bytes unlinked, actual free space before/after,
verification and total elapsed time, and any deletion error. Free-space delta
also includes concurrent host activity. The existing worker ZIP/package cleanup
already happens after import and is retained. This change does not claim that
those files previously leaked permanently or that the released space is enough
for every future case.

A single Actions-only check uses the exact retained T full6 checkpoint
13067209799, verifies its archive and manifest, makes a physical live mirror,
runs the actual cleanup, and rechecks every mirror hash and retained metadata.
Its added release control is explicitly synthetic because the original archive
predates release. It runs no VM, traffic, Bering, Sheaft, refitting or rescoring.
Unit, exact source/CI, real saved-prefix output and strict consumer reviews are
required before any new full-main replacement; those gates are not satisfied
by this document. All failed, qualification, cleanup and recovery costs remain.
