# DeepFlow OTel postcapture resource lifetime

Exact candidate source: `0056b4c8ecb85e8b40c433e63af442133a21f3cc`, based on
`f7ba801d70f9d2327031efc6dd0c00b90d252708`. It is intended only for the eight
technically failed DeepFlow OTel cells. All 73 completed negative, unknown or
adverse main cases remain retained and must not be replayed.

All targets, class tests, database and asynchronous terminal observations finish
under the original two live guest kernels. The unchanged final drain and native
capture preserve original raw files, barriers, closures, trace audits and logs.
The controller then closes collectors/application once, retains the original
guest check/serial/stat/dmesg commands, stops the two verified owned QEMU
processes through identity-bound process descriptors, confirms exit, and removes
only their two ephemeral `root.qcow2` files. It then performs the original host
ingest, identity/alias projection, class/evidence readout and frozen-file checks.
Later workflow retention verifies and reuses earlier guest diagnostics.

All collector, Store, identity, alias, model and application implementations
remain exactly S. The source profile requires all 33 reviewed tree entries and
all 2,110 unchanged entries, including file modes. Actual S/C/T/U/V input and
storage proofs retain their original tested sources. Each new main case must
also retain its own worker import/SQL/input/output/freeze/outcome and actual
guest-release/capture proofs; a technical qualifier cannot admit a main case.

The [actual two-guest lifecycle qualification](https://github.com/a-a-k/ebpf-model-discovery-experiments/actions/runs/41464411920)
passed at this exact source. It verified two independent boots, two owned process
exits, removal of only their overlays, unchanged closed control hashes and reuse
of retained diagnostics. Its controls were two copied source files, explicitly
not scientific observations; it ran no application traffic, Bering or Sheaft.
The [root](clean-study-postcapture-lifecycle-root-actual-review-20261102.json)
and [independent](clean-study-postcapture-lifecycle-independent-actual-review-20261102.json)
actual reviews record the scope and limits.

The earlier source's qualification
[41462775370](https://github.com/a-a-k/ebpf-model-discovery-experiments/actions/runs/41462775370)
failed because QEMU removed its own PID file on exit. The corrected source accepts
and records this outcome only after original process exit; present wrong PID
files remain fatal. The earlier code review also rejected an unbound signal path
and incomplete diagnostic-proof reuse; both were repaired before qualification.
All failed qualification and CI costs remain in the declarations.

Original live-parent memory contention and one actual ENOSPC failure motivated
the lifetime change. The boot-only qualification is not a full-workload memory,
disk or six-hour completion guarantee. The earlier fixed 100,000-row resolver
profile took 25.032 seconds in `resolve`; it did not establish a resolver-hours
bottleneck and was not used to justify a new resolver/cache. The complete 81-case
report and final independent review remain required.

## Actual first results, 2026-11-03

Full/6 completed and passed both case-evidence reviews. Its actual owned-guest
release took 2.673 seconds. The controller still spent 4,107.733 seconds between
release and completion: final ingest took 420.765 seconds and identity refresh
3,099.534 seconds. The remaining 587.433 seconds includes serialization,
evaluation, freeze checks and cleanup; it is not assigned to one unmeasured
function. Training identity refresh separately took 2,332.116 seconds. Refresh
counters exclude writing their own cost JSON.

The same source's absent/8 continuation failed with an actual GitHub ENOSPC
annotation. Absent/6 and /7 and partial/6, /7 and /8 were terminated by the
platform's six-hour limit. Their retained training packets do not identify the
exact lost continuation substage and do not provide completed scientific cases.
The replacement full/8 was also terminated at the six-hour limit. All seven
cases therefore lack completed final measurements. The lifecycle change is not
a demonstrated whole-matrix disk or execution-time cure. These failures and all associated
worker, wait, transfer, CI and qualification costs remain part of the study.

The separate fixed-worker import qualification
[41533099422](https://github.com/a-a-k/ebpf-model-discovery-experiments/actions/runs/41533099422)
retained all 13,059 logical paths, sizes, modes and hashes while sharing backing
storage only for verified closed discovery copies. Allocated bytes fell from
32,487,387,136 to 22,554,873,856: a saving of 9,932,513,280 bytes. Every original
ZIP member was still read to EOF and CRC-checked. This proves the fixed-artifact
storage result; it does not establish full-case headroom or a six-hour cure and
has not been admitted as a new scientific producer source.
