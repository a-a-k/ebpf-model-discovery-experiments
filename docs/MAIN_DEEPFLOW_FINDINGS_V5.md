# Main-study DeepFlow findings

This is a partial evidence review, not the completed 81-cell conclusion. Negative
and unavailable results remain part of the study and are not reasons to rerun a
technically complete case.

## Petclinic, absent SDK, repetition 6

The [original campaign job](https://github.com/a-a-k/ebpf-model-discovery-experiments/actions/runs/41164824120/job/124430032086)
completed at source `0c98bf4520e863ab021b60d00517ee2aa49ab38e`. The
[saved-evidence reader](https://github.com/a-a-k/ebpf-model-discovery-experiments/actions/runs/41302954468)
verified the preserved inputs without replaying traffic, fitting models or
recomputing predictions. The main agent and independent skeptic reviewed its
actual facts. Both admitted this case as a valid negative result.

There were 34,800 primary observations, including 9,600 independent target
observations, with two separate guest boots. Native training and final census
both contained zero application spans. The final raw snapshots and receiver
closure were retained; internal zero kernel or exporter loss remains unproven.

Bering actually constructed four pooled models: eBPF and combined sources, each
with raw and network views. Each accepted 1,682 input shards containing 430,322
spans. A collected graph therefore existed. Its saved operation bindings could
not establish the required gateway calls to customers, visits and vets or the
corresponding uniquely reachable database requirements. The recorded reasons
were missing or ambiguous calls and unresolved required callers or channels.
These facts do not establish the underlying physical cause or universal HTTP
incompatibility.

All four operations had unavailable predictions in both views for native, eBPF,
combined AND/OR and the prespecified context baseline: 32 paired rows in total.
The 24 primary branches contained no per-operation simulation command or model;
the eight context branches reused their unavailable frozen bindings. No Sheaft
forecast was fabricated for those branches. Bering's `traces: 0` counter is not
used to infer a cause. Route-family ARI of 1.0 with `no_positive_evidence` for all
600 classified test requests does not establish useful graph discovery.

Independent target successes were 2,400/2,400 for listing owners, 2,398/2,400
for listing vets, 2,099/2,400 for creating visits and 2,100/2,400 for owner
details with visits. The declared direct-contract baseline provided predictions
for all four operations: 1, 1, 0.875 and 0.875, respectively. The same supplied
semantics and inventory remain available to the source arms. No preparation-cost
advantage is claimed; human preparation effort is unknown.

The supported interpretation is narrow: this pinned DeepFlow configuration and
repetition did not supply sufficient operation-level evidence for useful Sheaft
forecasts when native tracing was absent. Repetitions 7/8 are assessed below;
the other Petclinic modes still require completion before the final comparison.

## DeathStarBench, partial SDK repetition 7 and full SDK repetition 6

The [saved-evidence reader](https://github.com/a-a-k/ebpf-model-discovery-experiments/actions/runs/41307478392)
checked the original source-bound packets from
[partial repetition 7](https://github.com/a-a-k/ebpf-model-discovery-experiments/actions/runs/41282001013)
and [full repetition 6](https://github.com/a-a-k/ebpf-model-discovery-experiments/actions/runs/41280950428).
Both the main agent and independent skeptic admitted the actual evidence. Each
case retained two independent guest boots, 34,800 primary observations including
9,600 target observations, frozen forecasts before targets, raw closure and
matching logical checkpoint/import proofs. Six pooled Bering models actually ran
per case; available primary forecasts have actual Sheaft commands, models and
successful execution records.

The eBPF-only arm could not bind any of the three complete operation paths in
either case. With full SDK tracing, native, combined and context arms predicted
compose/home/user success probabilities of 0.875/1/0.875. Independent successes
were 2,800/3,200, 3,200/3,200 and 2,800/3,200. With partial SDK tracing, only home
had an available forecast, 1, matching 3,200/3,200 outcomes; compose and user stayed
unknown, with 2,800/3,200 successes each. These are valid unsupported branches,
not technical failures to rerun.

Adding DeepFlow supplied observed database coverage: the combined home graph
covered its required database channels in both cases, and full-SDK compose
needed fewer assumed database requirements than native alone. Some compose and
user requirements remained assumed. This structural information did not add an
available primary operation forecast or improve an external primary prediction
over native/context. Primary forecasts also explicitly hold nonintervened
database requirements fulfilled; they do not prove complete database recovery.
Raw-view database-fault forecasts remained unavailable. In network scope,
combined/context home predicted 1 with the selected database both healthy and
down, matching 7/7 successes in each condition; other database-fault forecasts
remained unavailable. All 20 probe operations succeeded in each condition. This
zero-impact agreement does not demonstrate an added database-fault prognostic
benefit. An available binding flag alone does not establish a saved simulation:
the eBPF network binding had such a flag but no available operation forecast.
The recorded `db_down` phase also has 7/7 compose HTTP acknowledgements against
the direct database prediction of 0. A subsequent bounded audit of the original
full/6 packet confirms that the selected **user-timeline MongoDB** was stopped
after these requests and before restore; the separate post-storage MongoDB was
running. This is one phase-end observation, not continuous proof for every
request or evidence for all repetitions.

The pinned generated Lua client parses a declared `ServiceException` into
`result.se` but `recv_ComposePost` never checks or raises it. The HTTP handler
therefore can return its success acknowledgement after a declared backend
error. Pinned C++ awaits the upload futures and the selected MongoDB write path
throws on failure: neither cache use nor asynchronous completion is needed to
explain this source-level acknowledgement gap. The measured HTTP success does
not prove a successful database write. Actual reply structs were not inspected,
and the prebuilt backend image lacks a demonstrated build-source attestation;
this is not a complete causal trace of the seven replies. Preserve the original
prediction and 7/7 outcomes, without retroactive rescoring or application fixes.
The [root audit](clean-study-DSB-HTTP-ack-root-audit-20261101.json) and
[independent audit](clean-study-DSB-HTTP-ack-independent-audit-20261101.json)
record the exact source, original metadata member and limits.

The equal-information direct-contract baseline supplied all three primary
predictions, 0.875/1/0.875. No discovery or total-effort advantage follows from
matching it; human preparation costs remain unknown. These two cases support
the narrow conclusion that observed extra database edges can coexist with
unresolved operation paths and no demonstrated extra external utility. They do
not establish universal Thrift incompatibility or the completed 81-cell result.

operation forecasts unknown. Across partial repetitions 6/7/8, native,
combined and context support home only: prediction 1 and 3,200/3,200 target
successes; compose and user each have 2,800/3,200 successes but unavailable

Each new DSB case has six actual pooled Bering executions and actual Sheaft

Extra observed database coverage supplies information without establishing an
extra useful primary operation forecast in this pinned configuration.

The fifth batch brought the independently reviewed main subset to 65/81. The complete
three-collector study, remaining captures, final report and retention tail remain
unfinished. Paired method/view rows are not independent repetitions; all source,
preparation, worker wait, reader, failure and archive costs remain attributable,
and human preparation effort is unknown.

## Petclinic absent repetition 8: all three absent repeats reviewed

The existing [sixth saved reader](https://github.com/a-a-k/ebpf-model-discovery-experiments/actions/runs/41333444648)
checked only the original absent/8 packet; the first 65 cases were not replayed.
The [root review](clean-study-batch6-root-subset-review-20261101.json) and
[independent review](clean-study-batch6-independent-subset-review-20261101.json)
both admit the actual evidence. It contains 34,800 primary observations,
9,600 independent targets, 16 blocks, two distinct guest boots and genuinely
zero native training/final spans. Forecast bindings were frozen before targets.

Four pooled Bering calls each ingested 425,804 observations from 1,666 input
shards. The raw observed graph has 15 edges and 13 endpoints; the network view
has 13 edges and 13 endpoints. These differ from repetition 6 and are not empty
graphs. Required gateway-to-service and caller-to-database obligations remain
missing or ambiguous, so all 32 source/context operation forecasts are unknown.
No per-operation Sheaft execution is invented for an unavailable branch.

Owners and vets succeed 2,400/2,400; visits and owner details succeed
2,100/2,400, against direct primary predictions 1/1/0.875/0.875. The recorded
DB-down phase has 0/5 for owners, visits and details, versus 5/5 in the up phase;
vets have 5/5 in both. The direct vets DB prediction is conditional/unknown.
These selected facts do not independently establish the physical DB stop state
or the mechanism of that behavior. Kernel/exporter zero-loss remains unproved.

All three DeepFlow Petclinic absent repetitions therefore fail to provide
sufficient graph evidence for the requested operation forecasts in this pinned
configuration. This is an observed applicability limitation, not a reason to
replay a complete case or a universal impossibility claim. The independently
reviewed main subset is now **66/81**; the remaining 15 DeepFlow cases, complete
report and finite retention tail are still required.
