# Repository execution rules

## Active scientific scope

The active design is [PROTOCOL_V6.md](docs/PROTOCOL_V6.md) and its
[allocation amendment](docs/PROTOCOL_V6_ISOLATED_ARMS.md): 108 fresh cells,
three applications, absent/partial/full SDK coverage, none/OBI/Coroot/DeepFlow,
repetitions 9/10/11 and all ten operations. The no-agent arm is a real runtime
control. Historical 81-cell measurements and their costs remain separate.

The question is whether eBPF observations support executable operation models
and externally checked forecasts when SDK traces are missing or incomplete.
Compare native input, direct conditional calculation and cheap observed-context
unions with the same information and semantic knowledge. There is no requirement
to outperform an equivalent direct calculation. Model availability, graph size,
coverage and admission flags alone do not establish external usefulness.

Training and prospective validation use separate deployments with two actual
guest kernels. Freeze all four models before any validation target. Preserve
source identities, input closures, original identifiers, ambiguous ancestry and
actual producing runs/jobs/attempts. Do not invent topology or substitute labels
for observations. Unsupported, adverse, unavailable and UNKNOWN results remain
included. Valid negative results are not repeated to obtain a positive outcome.

Eight PC/OTel full/9 cells retain physical pairing; the remaining 100 use
randomized separate hosts. The interrupted DSB full/9 attempt and every prefix
remain historical evidence/cost. Its approved replacement uses four new captures,
models and isolated targets, without importing the old prefixes. No auxiliary or
short-smoke measurements fill a scientific cell.

## Execution and ownership

Application traffic, VMs, model construction, simulation, heavy artifact checks
and result processing run only in GitHub Actions. Local work is source editing,
static checks and focused synthetic unit checks. Reuse the collector -> Bering
-> Sheaft path; do not add generic validation, schema or retry frameworks.

The main maintainer owns common code, workflows, README, merges and dispatch.
Assigned application workers edit only their assigned worktrees and report
committed source IDs; they do not merge or dispatch independently. Scientific
implementation, hypothesis changes and success claims require an independent
check against the original criterion and strongest equally informed baseline.
Record both verdicts before execution and review actual external results before
claiming completion or usefulness.

Use the full standard Ubuntu 24.04 worker and 360-minute job limit, without
artificial CPU/RAM caps or max-parallel limits. Record actual host resources,
boot IDs, disk guards, phase times and costs. No paid runners or account changes
are authorized. Communication stays in the current conversation; Telegram and
Windows autostart entries are prohibited.

Do not download whole scientific archives, campaign/model data, raw journals or
SQL dumps locally. Retain compact selected metadata and hash-bound provenance.
Release only verified owned temporary deliveries after confirming publication;
preserve source, unique evidence, active worktrees and immutable cloud originals.
Do not restart historical bulk-download watchers. Fetch current Actions states
before reporting live counts and timestamp status inventories.

## Registered OTel processing continuation

Four failed MAIN blocks (partial/9, partial/10, partial/11 and absent/10) reuse
exactly their original four successful capture publications. Recompute all four
models under the same child-only GOGC=25 and additional owned 16 GiB model swap
profile; retain platform swap, physical CPU/RAM and job deadline. Use four fresh
isolated validation workers after the common model barrier. Preserve old capture,
case/reference/plan bytes and report genuine new processing/validation origins.
MAIN inputs cannot be cast as qualification inputs or relabelled with a new SHA.

OTel full/9 separately reuses its original qualification captures under the same
processing profile and retains its first fresh paired validation. All earlier
failed processing attempts and every successful output/cost remain included.
Full/10 and full/11 require separate exact-source approval after all four new
full/9 computations/publications and actual resource evidence are reviewed.
They may overlap its validation only with explicitly unobserved validation-budget
risk. A previous failed resource run does not qualify these eight cells.

Check disk plus reserve before exclusive no-symlink swap creation. Record its
before/after resources and setup CPU/wall costs. Full processing publication uses
same-filesystem hard links, streaming upload and a complete bytes/SHA/mode/mtime
manifest; verify the source and staging census before and after upload. Portable
model archives remain unchanged. Unfrozen processing is explicitly PARTIAL.
Do not reduce inputs, models, operation counts or baselines to fit resources.

Every continuation requires literal parent-input review, exact-source review,
required CI and prospective actual-run binding. Editing any counted source or
protocol byte requires a new implementation census and approval. Preserve sealed
historical registration/review records; publish new approvals separately.
Preparation, provisioning, builds, captures, model/simulation work, transfers,
failures, repeats, early stops, CI, review and publication count toward costs.
Unknown human or unmetered work remains UNKNOWN. Worker elapsed time is not CPU
time, billing or sequential campaign wall time. Technical recovery is not a
scientific result, and additional swap/GC does not establish universal fit.
